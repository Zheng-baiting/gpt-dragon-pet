## 测量方法

`npm run test:native` 启动本项目 Electron 窗口，通过仅绑定 localhost 的临时调试端口检查原版菜单、拖拽、点击与动画恢复，并分别测量当前点击回应和待机：

- 帧率使用 `requestVideoFrameCallback` 元数据的 `presentedFrames` 增量除以 `presentationTime` 增量。JavaScript 回调可能合并，回调调用次数不能直接代表呈现帧数。
- 掉帧使用当前前台视频的 `getVideoPlaybackQuality()` 增量，排除被暂停的后台视频丢弃预解码队列产生的计数。
- `requestAnimationFrame` 仅记录页面刷新间隔，不用于声称视频帧率。

原始报告与窗口截图保存在忽略提交的 `work/` 中。测量接口参见 [HTMLVideoElement.requestVideoFrameCallback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)。

```powershell
npm test
npm run check
$env:GPT_PET_MIN_FPS = '22'
npm run test:native
```

当前最低帧率检查为可选设置22fps；会解码基础视频，核对24fps时间基、108/58帧总数、透明通道和帧变化。

`assets/basic-preview.gif` 固定为 10 fps，供仓库页面缩略浏览；桌面播放使用 WebM 文件。


## 当前原版规格：640×360、24fps（2026-10-21）

用户明确取消120fps要求。21段正式视频与2段基础视频已统一640×360/24fps。正式16段241帧、5段121帧，共4461帧；基础108/58帧。正式成品总字节419317269→50481674（约减少88%），待机20287167→2399595。原始带标记MP4和旧Git历史保留。

21段全解码扫描：均24fps、透明背景、内容不触画布边界；绿边像素最大占比0.00000708，首尾Alpha平均差最大约0.068/255。20段非待机片逐段复核16个短桥样本，并检查全片中心动作抽样。来源内部画风差异和短桥局部柔化仍保留。

实际Electron合成检查：同一透明帧两个50%图层，普通source-over交叠实心区Alpha中位数190/255；隔离plus-lighter后254/255，8bit舍入平均误差约0.16/255。该修正避免淡化时的透明度下陷，不能改变模型绘制差异。

连续载入检查曾发现第三段重用video元素约0.54秒时PIPELINE_ERROR_DECODE：单次实播和FFmpeg全解码未发现。原版自定义协议对Range请求返回整片；项目副本补齐字节范围响应并禁用旧内容缓存后，待机→行礼→待机→忙碌→待机→哈欠→待机→挥手完整链及末尾返回待机通过。流式优化已撤销，仍读取宿主已校验的本地文件；不修改上游包。单测覆盖完整、开放区间、后缀区间、越界与HEAD请求。

同一观测方法下，旧片最后呈现至新片前台回调间隔约90.8～157.5ms，包含24fps帧间隔及回调时序；新片请求至前台回调约49.2～114.2ms。指标与旧120fps样本不能直接当成同帧率对照。旧片保留至淡化结束，正常首尾已有共同站姿，但仍不宣称任何换片都零等待。

七段单独实播（小憩、张望、叹气、归档、庆祝、拖拽、摇摆）各采样1.8秒为23.9634～23.9973fps，掉帧均0；监听真实ended并确认后续片已呈现、未处于ended状态。只代表此次样本，不保证任意负载一直零掉帧。

最终原生菜单/三级菜单、透明区穿透、拖拽悬空、松手位置与点击回待机检查通过；待机3秒24.0108fps、点击1.8秒23.9715fps，采样掉帧分别0/0。原测试把松手前200ms的debug位置与释放位置比较，仍在收敛的弹簧导致7～8px假失败；现改为比较pointerup紧前的权威sprite.pos与释放位置，不改物理或放宽1px阈值。
