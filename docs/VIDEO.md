# 按 dsh-pet 原项目制作完整动作

本项目直接复用 [PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet) 的 106 个逐动作配方与素材制作脚本，固定提交 cc623c7e78aaab7e708f5aede783c3de01b11964，与运行包 dsh-pet@0.3.7 一致。原作者用豆包生成动作视频，再做透明后期。这里将角色设定换成 Q 版 GPT 白龙娘，动作时序、构图和首尾站姿沿用原配方。

当前制作流程已接通，**21/106 个 GPT 动作已有透明视频**：十六段约 10.04 秒、1205 帧，五段约 5.04 秒、605 帧的完整短版。十八段为 1280×720，TapNow 的归档、张望、叹气三段仍为 640×360；全部为 120 fps，已用于预览。短版不代表完成原配方的十秒时序。两段基础动画独立计数，其余 85 个动作尚无素材；未取得成片或未通过检查的请求不计入数量。

## 1. 角色与动作配方

assets/gpt-video-reference.png 是完整龙角、翅膀和尾巴的 Q 版站姿参考。prompts/character.md 定义角色身份；vendor/dsh-pet/action-prompts.md 保留原版全部配方，scripts/recipes.mjs 按 assets/actions.json 的映射替换角色描述，保留各阶段动作安排。

~~~powershell
npm run media:prompt -- '待机呼吸休闲'
npm run media:recipes
~~~

后一条把全部 106 份可直接使用的 GPT 娘提示词导出到项目 work/recipes/，不联网。每份都包含角色定义、原版通用构图要求和该动作的按秒安排。sourceName 保留原动作名称，可对照原视频检查。

先制作待机，再制作拖拽悬空反馈、五种点击回应、移动和工作状态，最后补生活、玩耍与时节动作。每段约 10 秒，16:9，绿幕统一为 #00FF00，机位固定，人物不横向漂移，首尾回到同一正面站姿，道具按原配方出现并收回。

生成视频需要所选服务的账号和可用额度。上传参考图前须确认具体服务、素材范围和费用上限；本地脚本不会自动调用任何视频服务。此前为 Runway 准备的 3 秒换角试做文件仅留在 work/retarget/，不作为当前原版流程的依赖。

### 免费服务的短版素材

部分免费试用只开放 5 秒，不能直接完成原配方的十秒时序。这类素材保留动作的准备、主体、收势与无道具站姿四个阶段，逐段注明为五秒短版；不通过重复播放、减速或补帧冒充十秒原片。源片的实际尺寸、帧率、时长与调整记录保存在对应来源 JSON 中。

TapNow 的当前 Seedance 2.0 Mini 免费规格输出 836×480。后期只在左右各补九个绿色像素，得到接近 16:9 的 854×480 画布，再进入原版流程，避免拉伸人物。角色外的高处小特效若超出归一化画布，只调整与人物分离的特效区域；原始下载视频保留。源片中已经出画的道具无法靠此修复，须重做。

若动作末尾已经没有道具，但站姿与开头偏差明显，可将最后半秒替换为从第 108 帧回到首帧的缓入缓出双向光流过渡，再补到 120 fps。该修正须记录并复查，不能替代缺失的主体动作。生成片和后期片均检查首尾、动作中段与全片透明边界；快速跳跃仍可能有短暂补帧柔化。

## 2. 准备本地工具

使用已有 Python 与 FFmpeg，当前终端设置可执行文件路径，不修改系统 PATH：

~~~powershell
$env:GPT_PET_PYTHON = '你的已有Python目录\python.exe'
$env:GPT_PET_FFMPEG = '你的已有FFmpeg目录\ffmpeg.exe'
& $env:GPT_PET_PYTHON -m pip install --target work/tools/python --cache-dir work/pip-cache -r scripts/requirements-motion.txt
& $env:GPT_PET_PYTHON scripts/pipeline.py reference
~~~

参考图命令生成 work/generation/gpt-source-reference.png：1280×720，头顶约 20%、脚底约 85%，与原项目的生成构图一致。源参考图保留。

## 3. 原版后期处理与 120 fps

绿幕源视频：

~~~powershell
npm run media:process -- '待机呼吸休闲' 'D:\已有视频\idle.mp4' --chroma 0x00FF00
~~~

若画面边缘含生成服务标记，可在确认完整角色、道具与特效始终位于指定区域内后，限定角色提取区域：

~~~powershell
npm run media:process -- '点击回应-害羞惊讶' 'assets/sources/点击回应-害羞惊讶-doubao.mp4' --chroma 0x00FF00 --region 256,0,768,720
~~~

区域参数依次为原始画面的 x、y、宽、高。处理时用绿色补回原画布，保持角色坐标与比例；带 AI 标记的原片继续保存在来源目录。源视频本身已裁掉的头发或特效不能靠补边、补帧恢复，须重新生成。

720p 源片可选择更清晰的输出，先从归一化母版编码到 1280×720，再补帧，不放大已有的 360p 成品：

~~~powershell
npm run media:process -- '工作状态-忙碌点按' 'assets/sources/工作状态-忙碌点按-jimeng.mp4' --chroma 0x00FF00 --region 256,0,768,720 --height 720
~~~

高清中间文件位于 `work/pipeline-hd/<动作名>/`，与默认 360p 路线分开。每段仍需检查细节、透明边缘和实际播放；提高尺寸不能恢复源片已经模糊的细节。默认保持原版的 640×360 输出。

已手工抠像、含 Alpha 的 MOV 或 WebM：

~~~powershell
npm run media:process -- '待机呼吸休闲' 'D:\已有视频\idle.mov'
~~~

流程在项目内依次执行：

1. 绿幕视频预处理为原脚本所需的 1280×720、24 fps，运行原版 chroma_step02.py 的 HSV 抠像；白紫角色不含绿色，包装器在当前进程将绿色判定的最低明度设为 0，以清除生成片里的深绿色地面阴影，中性黑色线稿仍保留。手工抠像 MOV 则走原版 pr_import_step02.py。原作者现有动作使用手工抠像路线；自动抠像仍须检查白发和半透明边缘。
2. 运行原版 normalize_step03.py：按首尾站姿测量人物高度，归一化到 2160×1215 母版、角色高 900、脚底线 1115；扫描全片，拒绝对齐后会裁掉动作的构图。包装器将输入时间戳对齐到 24 fps 网格，避免末帧因毫秒取整丢失。
3. 运行原版 encode_thumbs.py：默认 640×360、24 fps 的透明 VP9 WebM；`--height 720` 时由包装器在当前进程改为 1280×720。本项目将质量设为 CRF 18。
4. 绿幕路线先清除白紫角色边缘的绿色染色，再在预乘 Alpha 空间用双向光流生成 120 fps 运动中间帧，保留动作时长，输出透明 WebM。手工 Alpha 输入保留原有颜色，不做绿色抑制。补帧不能补出源视频里没有的动作，仍需逐段检查人物和遮挡变化。

原脚本原样保存在 vendor/dsh-pet/，包装器仅在当前进程指定路径、尺寸、编码参数和线程限制。每次只处理一个动作，编解码和滤镜各限两个线程。原始输入不修改，中间文件均在 work/pipeline/<动作名>/：

- step02.webm：抠像结果。
- step03.webm：统一站姿的母版。
- step04-24fps.webm：原项目格式的播放视频。
- video-120fps.webm：120 fps 成品。
- review.png、report.json：六帧检查图与格式、对齐参数记录。

### 已检查动作的首尾修正

行礼、下蹲、惊醒、摇摆和高清待机在主体动作完成后，最后半秒用缓入缓出的双向光流接回首帧站姿，保留 1205 帧与原时长。需要重建相同修正时，在 720p 流程结束后运行：

~~~powershell
python scripts/finish-standing.py '龙娘屈膝礼仪'
~~~

小憩原片的独立睡眠气泡偏大、末尾仍残留；保留原片，使用来源目录中的两个脚本处理。先将原有气泡缩放到头顶安全区、在第 7～8.5 秒淡出，再走 Alpha 视频路线。最后清除头顶碰边的小块气泡残影，并修正末尾站姿：

~~~powershell
python assets/sources/原地小憩沉眠-processing.py
npm run media:process -- '原地小憩沉眠' 'work/video-edit/sleep-effects/prepared-24fps.webm' --height 720
python assets/sources/原地小憩沉眠-finishing.py
~~~

这些修正只调整已有像素与首尾衔接，不增加新的手绘姿势。来源 JSON 记录处理范围、输出摘要和逐帧扫描结果；重建后仍须查看生成片和实际播放。

## 4. 检查后导入

逐段看完整视频与检查图，确认人物、表情、手脚、龙角、翼和尾巴一致，首尾站姿衔接，透明边缘无绿边、残影或裁切。格式检查不能替代动作质量检查。

~~~powershell
npm run media:import -- '待机呼吸休闲' 'work/pipeline/待机呼吸休闲/video-120fps.webm'
npm run media:list
npm run check
~~~

行礼、高清哈欠与思考另试用了统一站姿衔接：前 0.45 秒从高清待机首帧经光流估计接入原片，最后约 0.46 秒接回同一帧，两端各有约 0.15 秒站定；中间完整动作保持原片。首尾姿态和色彩差异改为短过渡，仍可能有局部光流柔化。只对已逐帧抽查的片段应用，不能直接批量用于起始即有动作或结尾未完成的片段，也不解决中途打断。重建候选片：

```powershell
python scripts/finish-common-standing.py '龙娘屈膝礼仪'
```

输入默认为该动作 `work/pipeline-hd/` 下已经处理到 120 fps 的视频，参考为正式待机首帧，候选输出在 `work/video-edit/`；可用 `--input`、`--reference`、`--output` 显式指定。脚本不覆盖正式素材，须检查候选片的完整动作、十六个衔接时间点、Alpha 边界和实播，再导入。

导入只接受 640×360 或 1280×720、120 fps、无音轨、含透明背景且不超过 10.2 秒的 WebM；按字节复制，避免把 120 fps 再降成 30 fps，也不会覆盖已存在的动作。成品在 assets/webm/。重新启动 npm start 即可在预览中接入已完成的待机、点击、拖拽、移动及分类动作；缺少待机或点击素材时使用对应基础动画。保留固定状态顺序的事件池须该池素材齐全后才接入。全部 106 段齐全后执行 npm run start:full。

### 跨视频色彩一致性

以正式高清待机为统一基准，在相同中灰背景下对照全片多个阶段。检查头发和白紫服装的亮度、阴影和色调，也检查脸、角、翅膀、尾巴形状、人物比例与线条清晰度。色彩接近不能代替角色与动作验收；明显造型漂移或低清片仍须另行替换。

2026-10-21 对现有21段抽样比对后，校正五段明显偏白的可灵动作（小憩、下蹲、惊醒、摇摆、行礼）和偏暗的 Seko 哈欠。以1、2、4秒的实心浅色白紫材质为校准样本，按三个通道的20/50/80分位建立固定分段线性曲线，锚住暗部线条与纯白高光。曲线在主体动作期间固定，避免逐帧自动曝光引起明暗抽动。已有共同站姿的行礼和哈欠只在原首尾短桥内平滑接入校正，两端保留待机颜色。动作、帧数、时长和编码尺寸不变，透明通道在调色前后保持原像素，再编码带来微小量化差异。

每段的来源 JSON 中 `colourMatch` 保留校正前输出摘要与 Git 提交、参考摘要、三组分位参数和测量方法。`scripts/match-colour.py` 可从对应校正前的120 fps WebM重建候选，输入摘要不符时拒绝，防止重复调色：

```powershell
python scripts/match-colour.py '哈欠连天' 'work/colour-input.webm' 'work/video-edit/yawn-colour-candidate.webm'
```

重建后仍须检查十二个全片时间点、共同站姿边界、深浅两种背景和原生播放。固定曲线不能改变角色画风，也不能完全消除源片内部生成的光照变化；不要把材质分位指标当成角色一致性的自动通行证。新片必须与待机及相邻动作并排、连续切换检查，通过后再导入。

## 验证与运行逻辑

~~~powershell
npm test
& $env:GPT_PET_PYTHON scripts/test-pipeline.py
~~~

测试验证 106 个配方均对应原版动作、上游源文件摘要未变化，并用隔离的几何测试片验证绿幕抠像、居中、脚底、透明通道、时长和 120 fps。测试片不导入正式动作库。

菜单、双缓冲切换、随机权重、弹簧跟手、甩抛、落地和多屏几何继续来自原版运行底座；这些逻辑与生成视频中的人物肢体动作共同构成最终效果。
